# 07 隐藏维度对比实验结果分析

## 1. 本章核心问题

本实验对比：

```text
hidden_size = 64
hidden_size = 128
```

要回答：

- 隐藏维度变大后准确率怎么变？
- 参数量怎么变？
- 为什么会这样？
- 能不能说越大越好？

## 2. 控制变量

唯一主动改变：

```text
hidden_size
```

其他条件保持一致：

| 参数 | 值 |
| --- | --- |
| 数据集 | MNIST |
| 训练/验证/测试 | 54000 / 6000 / 10000 |
| Epoch | 10 |
| Batch Size | 128 |
| 优化器 | Adam |
| 学习率 | 0.001 |
| 随机种子 | 42 |
| RNN 层数 | 1 |
| 输入维度 | 28 |
| 类别数 | 10 |

## 3. 结果表

| 指标 | hidden=64 | hidden=128 |
| --- | ---: | ---: |
| 最佳 Epoch | 8 | 10 |
| 最佳验证 Accuracy | 94.18% | 96.88% |
| 独立测试 Accuracy | 94.34% | 97.07% |
| 最终训练 Accuracy | 94.35% | 96.81% |
| 测试 Loss | 0.2023 | 0.1124 |
| 参数量 | 6,666 | 21,514 |
| 总训练时间 | 201.01 秒 | 165.34 秒 |
| 平均每 Epoch | 19.90 秒 | 16.52 秒 |
| 吞吐量 | 2,686.38 样本/秒 | 3,266.03 样本/秒 |

## 4. 准确率怎么解释

`hidden=128` 测试准确率：

```text
97.07%
```

`hidden=64` 测试准确率：

```text
94.34%
```

提升：

```text
2.73 个百分点
```

原因：

- 128 维隐藏状态容量更大。
- 可以保存更多笔画和行间结构信息。
- 对手写数字的整体形状表达更充分。

## 5. 参数量怎么解释

参数量：

```text
hidden=64: 6,666
hidden=128: 21,514
```

隐藏维度增加后，RNN 内部输入到隐藏、隐藏到隐藏、隐藏到分类层的参数都会增加。

所以准确率提升的同时，模型复杂度也增加。

## 6. hidden_size 越大越好吗

不一定。

隐藏维度太小：

- 模型容量不足。
- 容易欠拟合。

隐藏维度太大：

- 参数量增加。
- 计算成本增加。
- 数据较少时可能过拟合。
- 收益可能递减。

正确说法：

> hidden_size 是模型容量的重要超参数，需要通过验证集和测试集结果判断合适大小。

## 7. 为什么 128 维这次反而更快

结果中 `hidden=128` 平均 Epoch 时间更短。

但不能说：

> 隐藏维度越大训练越快。

可能原因：

- 第一次运行有数据下载或缓存开销。
- CUDA 第一次使用有预热。
- 后台负载不同。
- 小模型计时波动较明显。

严谨做法：

```text
预热后重复多次，报告平均值和标准差。
```

## 8. 泛化情况

`hidden=64`：

```text
训练 Accuracy: 94.35%
测试 Accuracy: 94.34%
```

几乎一致。

`hidden=128`：

```text
训练 Accuracy: 96.81%
测试 Accuracy: 97.07%
```

测试略高。

这不表示模型“测试比训练更强”，只是统计波动、数据难度差异和 batch 统计方式造成的小差异。

整体看，两组没有明显过拟合。

## 9. 正确结论怎么说

> 在本实验中，隐藏维度从 64 增加到 128 后，测试准确率从 94.34% 提升到 97.07%，测试 Loss 也降低，说明更大的隐藏状态能保存更多笔画和行间结构信息。但参数量从 6,666 增加到 21,514，因此提升准确率的同时也增加了模型复杂度。
